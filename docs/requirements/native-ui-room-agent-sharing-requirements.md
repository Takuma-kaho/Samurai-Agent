# Native UI改善・Room中心の記憶管理・共有機能 要件定義書

- 作成日：2026-09-17
- 対象：今回のNative App改善スプリント
- 状態：利用者との合意に基づく要件ベースライン。実装済みを示す文書ではない。
- 目的：画面の不足、記憶の管理単位、共有の扱いを確定し、後続の設計・実装・受入確認の基準にする。

本書の「必須」「行う」「できる」は、今回のスプリントで満たす要件を表す。画面配置の細部、API名、物理テーブル、処理方式は後続の設計で具体化する。これらの設計判断を理由に、本書の対象機能を後続スプリントへ移さない。

## 1. 要件整理

### 1.1 背景と解決する問題

現在のNative UIは試作品の外枠と既存機能への接続を優先しており、検索、通知、参加者表示、設定への入口が不足している。Roomの階層や、既定Agent、成果物パネルの操作も利用者が把握しにくい。

記憶の管理では、Room、Agent、Workspace、本人の四つを同列の管理先にすると、保存先の判断と管理画面の往復が増える。このため、Workspace専用メモリーを廃止し、Roomの自動学習、Agentに持たせる知識、本人の設定を用途で分ける。共有は利用者が内容を選び、確認・編集して実行する。

### 1.2 用語と責務

| 用語 | 本書での意味 |
| --- | --- |
| Workspace | Room、Agent、メンバー、利用者所有データを管理する単位。データ所有、認可、export / restoreの境界を維持する。Workspace全体へ自動適用する専用メモリーは持たない。 |
| Room | 継続する会話・作業・知識・閲覧権限の境界。自動学習の基本単位。 |
| Agent | 人格、指示、Skill、明示的に持たせた知識・記憶を持つ作業主体。同じWorkspace内の複数Roomへ参加できるが、参加Roomの知識を自分の記憶へ自動吸収しない。 |
| 既定Agent | Roomへの通常の依頼を受ける1体のAgent。参加Agentの人数とは別に管理する。 |
| Agent DM | 本人と特定Agentの非公開の会話。Agentが1体だけの通常RoomをDMへ自動変換しない。 |
| Knowledge（知識） | 作業で再利用する内容。Roomで蓄積した知識と、Agentへ明示的に持たせた知識は帰属先を区別する。 |
| メモリー／記憶 | 再利用する情報を指す利用者向けの表現。共有時は、会話ログや学習途中の内部記録ではなく、選択した知識本文を対象にする。 |
| Skill | 再利用する手順。Room知識共有には含めず、Agent共有では選択対象にできる。 |
| 本人設定 | 名前、回答言語などの個人指示、表示テーマなど、本人に関する設定。Roomの自動学習とは別に管理する。 |
| Room管理者 | 対象Roomの管理権限を持つ利用者。既存のOwner / Admin等との対応は、現在の認可契約に従う。 |
| 共有物 | 発行者が確認した内容を固定したコピー。元のRoomやAgentそのものへのアクセス権ではない。 |

### 1.3 確定方針

| 項目 | 確定内容 |
| --- | --- |
| スプリント範囲 | Native UI改善、設定導線、Workspace専用メモリー廃止、Room知識共有、Agent共有をすべて含む。 |
| Workspace配置 | 左ナビゲーション上部に固定し、現在のWorkspace表示と切り替えを行う。 |
| 検索 | 選択中Workspaceの、本人が閲覧できるRoom・会話・Knowledgeを検索する。 |
| 通知 | 依頼の完了・失敗・承認待ち・入力待ち・招待を初期対象にする。通知一覧は選択中Workspaceに限定し、他Workspaceの未読は上部のWorkspace切り替え部分で知らせる。未参加Workspaceへの本人宛て招待は別枠で確認できる。 |
| 学習 | 自動学習はRoom内で完結する。Workspace、Agent、本人への自動的な知識の転記を行わない。 |
| 既定Agent | 1 Roomにつき1体を維持する。複数の既定Agentを設定する機能は追加しない。 |
| Room共有 | 選択した知識だけを共有し、受け手が指定する既存Roomへ独立した知識として取り込む。 |
| Agent共有 | 名前・人格・指示・選択したSkill・Agentの知識／記憶を共有し、受け手のWorkspaceへ独立したAgentとして取り込む。 |
| 公開範囲 | 限定共有と公開共有を選び、リンクで配布する。公開カタログは作らない。 |
| 共有停止 | リンクを無効化できる。取り込み済みのコピーは回収・削除しない。 |
| 既存データ | Workspace専用メモリーはリリース前の検証用データとして扱い、引き継がない。移管、救済用保管、移行専用画面は作らない。 |

### 1.4 現行文書・実装との関係

製品の所有境界とCoreの責務は、[PRODUCT.md](../../PRODUCT.md)と[ARCHITECTURE.md](../../ARCHITECTURE.md)を維持する。「Workspaceが知識の正本を所有する」ことは、「Workspace専用メモリーを全Roomへ適用する」ことを意味しない。

比較対象は[Native UI移行](../designs/native-ui-migration.md)、[Native App](../designs/native-app.md)、[RoomとAgentの共同作業](../designs/room-agent-work.md)、[Organization](../designs/organization.md)、[Artifact・Surface](../designs/artifact-surface.md)とする。今回変更する点は以下のとおり。

- 本人メニュー内のWorkspace切り替えを左ナビゲーション上部へ移す。テーマ選択は新設する設定画面へ集約する。
- Room単位を基本にした従来の検索記述を、選択中Workspace内の権限付き検索へ変更する。
- Workspace共通知識の管理・参照・昇格を廃止する。学習設定や権限ポリシーなど、メモリー以外のWorkspace設定まで一括削除しない。
- 前回のUI移行で表示対象外だった検索、通知、参加者、設定等を今回の対象に加える。

現行の[Completion service](../../packages/workspace-server/src/workspace-completion-service.ts)にはWorkspaceへの昇格と共通知識の参照経路があり、[schema](../../packages/workspace-server/src/schema.ts)にはWorkspace／Roomの資源スコープがある。これはソース確認による事実であり、実DB内のデータ存在は確認していない。実データの有無にかかわらず、今回の引き継ぎ不要方針を適用する。

## 2. 業務要件定義

### 2.1 利用目的

| ID | 利用者が実現すること | 成立条件 |
| --- | --- | --- |
| B-01 | 作業するWorkspaceとRoomを選ぶ | 現在地、Roomの親子関係、DMとの違いを画面上で判断できる。 |
| B-02 | 過去の会話や知識を探す | Roomを一つずつ開かず、選択中Workspaceの閲覧可能な情報へ到達できる。 |
| B-03 | 作業の結果と対応待ちを把握する | 通知から対象の依頼、承認、入力要求、招待へ移動できる。 |
| B-04 | 設定と記憶を管理する | 本人、Room、Agentそれぞれの入口から対象を確認・編集でき、Workspace専用メモリーの管理先を選ばされない。 |
| B-05 | Roomで得た知識を再利用してもらう | Roomの閲覧権限や会話履歴を渡さず、管理者が選んだ知識だけを共有できる。 |
| B-06 | Agentを再利用してもらう | 管理権限者がAgentの構成と選択した知識を共有し、受け手が独立したAgentを所有できる。 |

### 2.2 業務フロー

**通常の作業**：Workspaceを選ぶ → 階層一覧からRoomを開く → 参加者と既定Agentを確認する → 依頼する → 通知から結果または対応待ちへ戻る。必要な過去情報はWorkspace検索から開く。

**記憶の確認**：Roomのメニューから知識・学習設定を開く → 内容と根拠を確認する → 権限に従って修正する → 元のRoomへ戻る。Agentの知識はAgent詳細から、本人の個人指示は本人設定から扱う。

**Room知識共有**：共有元Roomの管理者が知識を選ぶ → 共有用の内容を確認・編集する → 公開範囲と限定共有の相手を指定する → 最終確認後にリンクを発行する → 受け手が共有内容を確認する → 管理権限を持つ既存Roomを選んで取り込む。

**Agent共有**：Agentの編集・管理権限者が対象Agentと共有項目を選ぶ → 共有用の内容を確認・編集する → 公開範囲と限定共有の相手を指定する → 最終確認後にリンクを発行する → 受け手が共有内容を確認する → Agent作成権限を持つWorkspaceへ新しいAgentとして取り込む。

共有用の編集は元データを変更しない。取り込みによって元のRoomへの参加、元Agentの共同編集権限、元のBackend認証を取得しない。

### 2.3 権限ルール

| 操作 | 必要な権限・条件 |
| --- | --- |
| Room一覧、会話、Knowledge、検索結果の閲覧 | 対象Workspaceへのアクセスと対象Roomの閲覧権限。DMにも本人用の既存認可を適用する。 |
| Room設定、既定Agentの変更 | 対象Roomの管理権限。変更するAgentにもRoomで必要な権限があること。 |
| Room知識の共有発行・共有停止 | 共有元Roomの管理権限。共有する知識がそのRoomに属すること。 |
| Room知識の取り込み | 有効な共有物の閲覧権限と、取り込み先の既存Roomの管理権限。 |
| Agent共有の発行・共有停止 | 共有元Agentの編集・管理権限。含めるSkillと知識を参照できること。 |
| Agentの取り込み | 有効な共有物の閲覧権限と、取り込み先WorkspaceでのAgent作成権限。 |
| 限定共有の閲覧 | ログイン済みで、共有物に指定された受信者本人であること。元Roomの参加者である必要はない。 |
| 公開共有の閲覧 | 有効なリンクを持つこと。ログインは不要。取り込みにはログインと取り込み先の権限が必要。 |
| 通知の閲覧・応答 | 通知の受信対象者であること。関連内容の閲覧・応答時にも、それぞれの現在の権限を確認する。 |

Organizationへの所属や役職だけで、Roomの閲覧・共有・取り込み権限を付与しない。Clientの表示制御だけに依存せず、Coreが各操作を認可する。

## 3. システム化範囲の決定

### 3.1 今回実装する範囲

| 区分 | 対象 | 対応する機能要件 |
| --- | --- | --- |
| ナビゲーション | Workspace上部固定、切り替え、Room階層の展開・折りたたみ、DMの区別 | F-NAV |
| 情報への入口 | Workspace検索、通知一覧と対象への移動 | F-SEARCH、F-NOTIFY |
| Roomヘッダー | 参加者、既定Agent、Roomメニュー、サイドナビと成果物パネルの開閉 | F-HEADER |
| 設定・記憶 | 本人設定画面、テーマ、Room設定と知識、Agent詳細と知識への入口 | F-SETTINGS、F-MEMORY |
| 概念と実装の整理 | Workspace専用メモリーの保存・取得・実行時参照・昇格経路の廃止 | F-REMOVE |
| 共有 | Room知識共有、Agent共有、限定／公開リンク、確認・編集、取り込み、共有停止 | F-SHARE、F-ROOM-SHARE、F-AGENT-SHARE |
| 必要な基盤変更 | 上記を成立させるClient、公開API、Core、データ保存、認可、検証の変更 | 第5〜8章 |

### 3.2 今回追加しない機能

- 複数の既定Agent、Agent数による通常RoomとDMの自動切り替え。
- Workspace専用メモリー、Workspaceへの知識昇格、Workspace／Agent／本人を起点とする自動学習。
- Room全体の複製、Room共有による会話履歴・Skill・設定・参加者・権限の配布。
- Room間の常時接続、共有物と取り込み先の継続同期、取り込み済みデータの遠隔回収。
- 公開共有を探すためのカタログ、マーケットプレイス、ランキング。
- Organizationの新しい管理体系、Workspace管理機能の全面拡充。
- 外部メール、Slack等への通知配信、新しいAgent Backend、新しい学習アルゴリズム。
- 検証用Workspace専用メモリーの引き継ぎ、利用者による移行作業、移行専用画面。

### 3.3 後続設計で具体化する事項

設計で決めるのは、設定画面のページ構成、アイコンと配置の細部、検索結果の並び方、Room内検索を併設するか、APIとデータ構造、通知イベントの対応表、共有リンクの技術方式である。必須のWorkspace検索、共有時の確認、公開範囲、認可、独立コピーという要件は変更しない。Room内検索の併設は、今回の受入条件には含めない。

## 4. 機能要件定義

### 4.1 ナビゲーション（F-NAV）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-NAV-01 | 左ナビゲーション上部に現在のWorkspace名と切り替え操作を置く。本人メニューを開かずに切り替えられる。 | 別Workspaceを選ぶと、そのWorkspaceの閲覧可能なRoom・DMへ一覧が切り替わる。 |
| F-NAV-02 | Roomの親子関係を階層として表示し、子Roomを展開・折りたたみできる。Room選択と階層開閉は別操作にする。 | 子Roomがある親を折りたたむと子が隠れ、再展開で戻る。開閉だけで選択中Roomが変わらない。 |
| F-NAV-03 | 通常RoomとDMを区別して表示する。閲覧できないRoom名や階層情報を表示しない。 | 他人のDMや権限外Roomが一覧・補足表示に現れない。階層表示を理由に閲覧権限を付与しない。 |
| F-NAV-04 | Workspaceの識別にはServer接続とWorkspace IDを用いる。選択時に対象Serverで再認可する。 | 異なるServerに同じWorkspace IDがあっても、Roomや検索結果が混ざらない。Organization未所属でも切り替えられる。 |

### 4.2 Workspace検索（F-SEARCH）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-SEARCH-01 | 左ナビゲーションに検索への入口を置く。検索範囲は現在選択しているWorkspaceとする。 | 複数Roomに一致する情報がある場合、閲覧可能な各Roomの結果を一度の検索で得られる。別Workspaceの結果は出ない。 |
| F-SEARCH-02 | Room名、会話本文、RoomのKnowledgeの題名・本文を検索対象にする。閲覧可能なDMも会話検索の対象とする。 | 各種別の一致結果を取得でき、結果から対象Room、該当会話、Knowledgeを開ける。内部Sessionの選択を要求しない。 |
| F-SEARCH-03 | 検索結果、抜粋、件数、候補表示のすべてに現在の閲覧権限を適用する。 | 権限外Roomの情報がいずれの表示にも含まれない。結果を開く時点で権限が失われていれば内容を返さない。 |
| F-SEARCH-04 | 検索中、該当なし、取得失敗を区別する。Workspace切り替え前の応答を新Workspaceへ表示しない。 | 通信失敗を「0件」と扱わず、切り替え後に旧Workspaceの結果が表示されない。 |

### 4.3 通知（F-NOTIFY）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-NOTIFY-01 | 左ナビゲーションに通知への入口を設け、未読の有無と通知一覧を確認できるようにする。通知を既読にできる。 | 新しい対象イベントが通知され、既読状態が再表示後も維持される。 |
| F-NOTIFY-02 | 依頼の完了・失敗は依頼者へ、承認待ち・入力待ちは対応対象者へ、招待は招待された本人へ通知する。 | 5種類それぞれについて対象者に届き、対象外の利用者へ内容を配信しない。 |
| F-NOTIFY-03 | 通知から関連する依頼、承認・入力要求、招待へ移動できる。通知を開くだけでは承認・入力送信・招待受諾を実行しない。 | 対象画面で本人が応答できる。処理済み・取消済みの要求を再実行しない。 |
| F-NOTIFY-04 | 未参加Workspaceへの本人宛て招待も確認できる。作業内容の通知では対象Roomの閲覧権限を守る。 | Workspace未参加を理由に本人宛て招待が隠れず、招待表示からWorkspace内の会話が漏れない。 |
| F-NOTIFY-05 | 通知の再取得・再接続で同じイベントを重複表示しない。種類を識別して扱い、後から種類を追加できる構造にする。 | 同一イベントの再配信で通知が増殖しない。知らない種類を受信しても他の通知を表示できる。 |
| F-NOTIFY-06 | 通知一覧は選択中Workspace内に限定する。他Workspaceの未読は上部のWorkspace切り替え部分に表示し、切り替えるとそのWorkspaceの通知を確認できる。 | 通知本文をWorkspace横断で混在させず、他Workspaceの未読があることに気づける。取得できないWorkspaceを未読0件として扱わない。未参加Workspaceへの本人宛て招待は別枠に表示する。 |

### 4.4 Roomヘッダー（F-HEADER）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-HEADER-01 | 開いているRoomの参加ユーザーと参加Agentを確認する入口をヘッダーに置く。 | 実際の参加情報を確認できる。架空の参加者や、参加を意味しないオンライン状態で代用しない。 |
| F-HEADER-02 | 既定Agentを識別できる表示を置き、詳細と管理権限に応じた変更操作へ到達できる。 | 参加Agentが複数でも既定は1体と判別できる。変更は新しい依頼へ適用し、実行中の担当を黙って変更しない。 |
| F-HEADER-03 | 既定Agentが未設定・無効・接続不能の場合は理由と設定または復旧への入口を示す。 | 履歴を保持し、別Agentを自動で既定にせず、実行不能を成功表示しない。 |
| F-HEADER-04 | RoomメニューからRoom設定と知識共有へ進める。サイドナビと右側の成果物パネルを開閉できる操作を設ける。 | 各操作の対象と開閉状態が分かる。現在の「成果物」テキストボタンはパネル開閉として分かる操作へ置き換え、成果物の閲覧・編集機能を維持する。 |

### 4.5 設定と記憶への入口（F-SETTINGS、F-MEMORY）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-SETTINGS-01 | 左下の本人メニューの設定ボタンから、左に項目・右に詳細を置く全画面の本人設定を開ける。本人のプロフィール、個人指示・回答言語、表示テーマを本人向け項目としてまとめる。 | 操作対象が本人であることが分かり、保存後に設定が反映される。他人の設定を変更しない。 |
| F-SETTINGS-02 | 現在の3テーマを設定画面で選択できる。既存のテーマ選択値と端末内保存の扱いを維持する。 | テーマ変更で会話入力、返信対象、実行、未保存の成果物編集が失われない。 |
| F-SETTINGS-03 | Roomヘッダーの三点メニューから、チャット右側の専用パネルでRoom設定を開ける。参加者、既定Agent、Roomの知識・自動学習の設定への入口をまとめる。 | 現在のRoomを対象として開き、管理権限のない利用者が設定変更を実行できない。 |
| F-MEMORY-01 | Roomの知識はRoom設定・メニューから一覧、本文、根拠へ到達し、既存の権限に従って確認・編集できる。 | 対象Roomが明示され、他Roomの知識が無断で混ざらない。メインの会話画面に管理一覧を常設しない。 |
| F-MEMORY-02 | Agentの知識・記憶はAgent詳細から確認・編集でき、Agent共有時に選択できる。 | 対象Agentが明示される。同じAgentを別Roomで利用してもRoomの知識と混同せず、元Roomの履歴を参照権限なしに取得しない。 |
| F-MEMORY-03 | 自動学習で生成・更新する知識は学習元Roomへ帰属させる。 | Agentを別Roomへ参加させても、前のRoomで自動学習した内容がAgentの持ち物として渡らない。 |
| F-MEMORY-04 | 本人の個人指示は本人設定として扱う。Workspace専用メモリー画面や、四つの保存先を選ばせる共通メモリー画面は設けない。 | Room、Agent、本人それぞれの対象から管理でき、通常の編集でWorkspaceメモリーへの保存を要求されない。 |

### 4.6 Workspace専用メモリーの廃止（F-REMOVE）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-REMOVE-01 | Workspace共通の知識・記憶について、新規作成、更新、Roomからの昇格、通常取得、検索、Agent実行への注入を廃止する。 | UIを隠すだけでなく、API直接呼び出しでも作成・昇格できず、検索・実行に旧データが含まれない。 |
| F-REMOVE-02 | 廃止対象の検証用データは引き継がず、関連する保存データ・索引・参照を整合性を保って除去する。 | RoomやAgentへ自動移管しない。廃止対象への参照が検索や実行に残らない。 |
| F-REMOVE-03 | Workspaceの所有権、メンバー、Room、Agent、export / restore、専用メモリー以外の設定・Skill・policyを維持する。 | Workspaceスコープという理由だけで他種別の資源を一括削除しない。復元処理から廃止対象が再生成されない。 |

### 4.7 共有に共通する機能（F-SHARE）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-SHARE-01 | 共有項目を選択し、共有用の本文・内容を確認・編集できる。最終確認には公開範囲、限定共有の相手、共有される項目と内容を表示する。 | 確認した内容だけが発行される。元データの更新が後から共有物へ混入せず、共有用の編集で元データが変わらない。 |
| F-SHARE-02 | 限定共有または公開共有を選んでリンクを発行する。限定共有では受信者を指定する。 | 第2.3節の閲覧条件を満たす人だけが共有物を読める。限定リンクの転送だけでは別人が閲覧できない。 |
| F-SHARE-03 | リンク先には共有用に確定した内容だけを表示する。会話履歴、認証情報、元Roomへの非公開参照を含めない。 | 本文以外の添付、根拠リンク、メタデータ、内部ID経由でも除外対象を取得できない。元Roomの閲覧権限は増えない。 |
| F-SHARE-04 | 受け手は取り込み内容と取り込み先を確認し、明示操作で取り込む。 | リンクを開いただけではデータ追加やAgent実行が始まらない。権限のない取り込み先を指定するとCoreが拒否する。 |
| F-SHARE-05 | 取り込んだデータは受け手側の独立コピーとする。 | 元データや共有物の変更・削除、元Roomの後続学習が取り込み済みコピーを書き換えない。コピー側の編集も共有元へ反映しない。 |
| F-SHARE-06 | 発行側は共有元の管理画面からリンクを確認し、共有を停止できる。 | 停止後の閲覧・新規取り込みを拒否する。停止前に完了した取り込み先のデータは削除しない。 |
| F-SHARE-07 | 発行・取り込み・停止の結果を表示する。失敗時は原因を示し、内容を成功扱いしない。 | 再送で同じ取り込みが二重作成されず、失敗した操作の不完全なAgentや知識が利用可能にならない。 |

共有停止は、すでに相手が読んだ内容や取得済みコピーを消す操作ではない。この点を発行前の確認と停止操作で説明する。

### 4.8 Room知識共有（F-ROOM-SHARE）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-ROOM-SHARE-01 | 共有元Roomの管理者だけが、同Roomに属する知識を選択して共有できる。 | 非管理者の発行、および別Roomの知識IDを指定した発行を拒否する。 |
| F-ROOM-SHARE-02 | 対象は選択した知識の題名・本文など、確認画面に表示する知識内容に限定する。Skill、設定、会話履歴を含めない。 | 自動学習で得た知識は選べるが、学習元の会話や根拠資料を芋づる式に公開しない。 |
| F-ROOM-SHARE-03 | 受け手が管理する既存Roomへ新しい知識として取り込む。Room自体は複製しない。 | 選択したRoomの知識一覧に追加される。共有元のメンバー、既定Agent、設定は取り込まれない。既存知識を無断で上書きしない。 |

### 4.9 Agent共有（F-AGENT-SHARE）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| F-AGENT-SHARE-01 | Agentの編集・管理権限者が、名前・人格・指示・選択したSkill・Agentの知識／記憶を共有する。 | 含まれる項目を確認・編集でき、未選択のSkill・知識は共有されない。 |
| F-AGENT-SHARE-02 | Agentの参加Roomの知識・会話履歴、本人の設定、Backend認証情報、元のアクセス権限を共有物へ含めない。 | 共有元Agentが非公開Roomに参加していても、その情報や権限が受け手へ渡らない。 |
| F-AGENT-SHARE-03 | 受け手がAgent作成権限を持つWorkspaceに、新しいIDの独立したAgentとして取り込む。 | 同名Agentがいても既存Agentを上書きしない。取り込んだSkill・知識を受け手側で管理できる。 |
| F-AGENT-SHARE-04 | 実行には受け手側のBackend接続・認証・Room権限を使う。 | 接続不足時は設定へ案内する。共有リンクの閲覧や取り込みだけでSkillを実行せず、取り込んだAgentをRoomの既定に自動設定しない。 |

## 5. 非機能要件定義

数値の根拠がない応答時間や稼働率を合意済みSLAとして設定しない。本スプリントでは、以下の観測可能な条件を品質基準とする。

| ID | 分類 | 要件・確認方法 |
| --- | --- | --- |
| N-01 | 認可 | 一覧・検索・通知・共有・取り込み・設定変更をCoreで認可する。権限の異なる複数Accountによる許可／拒否、APIへの直接入力、操作途中の権限取消を検証する。 |
| N-02 | プライバシー | 共有先へ渡る本文・リンク・添付・メタデータを確認し、除外対象がないことを検証する。公開共有であっても元RoomのAPIへアクセス権を与えない。 |
| N-03 | データ整合性 | 同じ操作の再送で二重発行・二重取り込みを起こさない。同時編集は版を照合し、未確認の上書きを拒否する。部分失敗で利用可能な不完全データを残さない。 |
| N-04 | 状態分離 | Workspace／Room切り替え、ログアウト、権限失効後に古い応答やキャッシュを別の対象へ表示しない。同じIDを持つ別Serverでも検証する。 |
| N-05 | 再接続 | 通知と作業状態を保存済み状態から再取得できる。リアルタイム配信を逃しても結果・対応待ちが消えず、重複もしない。 |
| N-06 | 操作性 | 検索、通知、設定、共有、パネル開閉をキーボードで操作できる。アイコンには操作名と状態を付け、色だけで未読・選択・失敗を区別しない。 |
| N-07 | 表示と入力保護 | 既存の3テーマとサポート対象の画面幅で主要操作へ到達できる。設定やパネルの開閉で、会話入力と未保存編集を失わない。 |
| N-08 | 一覧・取得処理 | 検索・通知・知識一覧は分割取得できる。Workspace全会話の本文をClientへ取得してから権限選別・検索する方式にしない。検索中も画面操作を妨げない。 |
| N-09 | 障害表示 | 通信失敗、権限不足、共有停止、接続不足、競合、処理済みを判別して表示する。失敗を空一覧・保存成功・取り込み成功に置き換えない。 |
| N-10 | 保守性 | Native Appと外部Clientが共通の認可・業務処理を使う。通知種類と共有対象の種類を識別して扱い、追加時に既存種別の意味を変更しない。 |
| N-11 | 操作記録 | 共有の発行・取り込み・停止について、操作主体、対象、時刻、結果を追跡できる。認証情報や限定リンクのアクセス用秘密を通常ログへ出力しない。 |
| N-12 | 回帰防止 | 通常依頼、返信、Room／DMの分離、既定Agent、成果物編集・保存、Workspace切り替え、export / restoreの既存契約を検証する。未実施の実Client・実DB確認を成功扱いしない。 |

## 6. データ要件定義

### 6.1 論理データと保持する情報

物理テーブル名と保存形式は設計で決める。PostgreSQLによるID・関係・権限・履歴の管理、利用者所有本文のファイル保存という既存の責務を維持する。

| データ | 必須情報・制約 |
| --- | --- |
| Workspace選択 | Server接続識別子、Workspace ID。別Serverの同一IDと区別する。 |
| Room | 所属Workspace、Room ID、親Room、種別、参加者・権限、既定Agent。通常RoomとAgent DMの認可上の違いを維持する。 |
| Room知識 | 所属Workspace、帰属Room、知識ID、題名・本文、版、作成・更新情報、既存の根拠情報。共有時は本文と非公開の根拠参照を分離する。 |
| Agent | 所属Workspace、Agent ID、名前・人格・指示、Skillとの関係、Agentの知識／記憶との関係、編集・管理権限、実行接続の参照。認証情報の本文を共有用データに持たせない。 |
| 本人設定 | 本人識別子、個人指示・回答言語、適用範囲。テーマは既存の端末単位設定を維持する。 |
| 通知 | 通知ID、受信者、種類、元イベント、関連Workspace／Room／依頼または招待の参照、発生時刻、既読状態。受信者と元イベントにより重複を防ぐ。 |
| 共有物 | 共有ID、Room知識／Agentの種別、発行者、共有元の内部参照、確認済みの内容、公開範囲、限定受信者、発行時刻、有効／停止状態。内部参照は公開本文へ自動出力しない。 |
| 取り込み記録 | 操作ID、共有ID、取り込み実行者、取り込み先Workspace／Room、新規作成した資源のID、時刻、結果。同じ操作の再送を識別する。 |

### 6.2 データの不変条件

1. Roomの自動学習結果は当該Roomに帰属する。Agentの参加先変更によって帰属先を変更しない。
2. Agentの知識を同じAgentとともに別Roomで使う場合も、元Roomの会話や知識を追加取得する権限は生じない。
3. Workspace所有のデータであることと、Workspace全員が参照できる専用メモリーであることを区別する。
4. 新たなWorkspace専用メモリーを作成しない。廃止対象をAgentの知識や通常Roomへ自動変換しない。
5. 共有物は確認済み内容の固定コピーとする。発行後の元データ変更を追従させない。内容を変えて再共有する場合も確認・発行を経る。
6. 取り込みでは新しい資源IDを採番し、取り込み先の所有・権限を適用する。共有元の権限・参加関係を複製しない。
7. 取り込み元の識別情報を記録しても、元Roomの非公開情報を閲覧できるリンクとして公開しない。
8. 共有停止後は新規の閲覧・取り込みを許可しない。すでに完了した取り込みは独立したデータとして維持する。
9. 検索索引やキャッシュが存在しても、現在の権限を迂回して内容を返さない。
10. 検証用Workspace専用メモリーの除去で、Room知識、Agent、Skill、policy、本人設定、会話履歴を巻き込まない。

### 6.3 保存・復元と互換性

- 新しい共有・取り込みデータも、Workspaceの所有境界とバックアップ対象に整合させる。
- export / restoreで取り込み済みの独立データを失わない。共有リンクの停止状態を復元によって有効へ戻さない。
- 旧データ形式や旧APIからWorkspace専用メモリーを再投入しない。廃止対象を含む旧入力は、対象と拒否理由を示して拒否する。RoomやAgentへ変換して救済する互換処理は設けない。
- 検証用データを引き継ぐための変換処理、Roomへの再配置、保管画面は要求しない。

## 7. 外部システム連携要件

| ID | 連携先・境界 | 要件 |
| --- | --- | --- |
| E-01 | Native App／公開API／Workspace Core | 検索、通知、設定、共有、取り込みを既存の公開API体系へ接続する。認可とデータ更新をClient専用実装にしない。 |
| E-02 | ブラウザーと共有リンク | 公開リンクは未ログインのブラウザーで確認済み内容を閲覧できる。限定リンクはログイン後に指定受信者を照合する。取り込み時はログイン済み利用者の取り込み先を確認する。 |
| E-03 | 共有元と取り込み先 | 共有元が共有物の閲覧可否を、取り込み先Coreが書き込み可否を判断する。元Roomへの参加権限を代用しない。接続先Serverが異なる場合もID・認証・権限を混同しない。 |
| E-04 | 認証・招待 | 現在の認証基盤と招待処理を利用する。限定共有の受信者を表示名だけで照合しない。共有リンクとWorkspace／Roomへの招待を別の操作として扱う。 |
| E-05 | Runtime／Agent Backend | 既定Agentの実行と承認・入力待ちは既存契約を利用する。共有Agentの取り込みによって提供元の認証情報、実行環境、ローカルパスへのアクセスを受け継がない。 |
| E-06 | Event／通知 | 完了・失敗・承認待ち・入力待ち・招待の保存済みイベントや状態から通知を生成する。切断後は履歴と現在状態から再取得する。通知画面の閲覧を業務上の承認と扱わない。 |
| E-07 | 保存基盤 | 既存のPostgreSQLとWorkspaceの本文保存先を使う。共有用の本文を切り出しても、元の非公開ファイルを無認可で公開しない。 |

今回の共有はSamuraiの共有物をリンクで配布する機能である。他社Botサービスとの互換インポートや、Buzz／GrokBotへの直接接続は要件に含めない。外部通知配信サービスの導入も今回の前提にしない。

## 8. 運用移行要件

### 8.1 既存データの扱い

| ID | 要件 |
| --- | --- |
| O-01 | Workspace専用メモリーは検証用データとして引き継がない。既存件数の有無を、Roomへの移管や利用者への再確認の条件にしない。 |
| O-02 | 廃止対象のデータ・索引・参照を特定して除去する。廃止対象以外を含むDB全体やWorkspace全体の初期化は行わない。 |
| O-03 | 専用メモリーの旧入力・参照・昇格経路を停止し、旧Clientや復元処理からの再作成も防ぐ。単に画面を非表示にして完了としない。 |
| O-04 | テーマ、既存Room階層、DM、参加者、既定Agent、会話、成果物、廃止対象以外の知識・設定を維持する。既存のWorkspace切り替え先は新しい上部入口から選択できるようにする。 |
| O-05 | 新しい機能はUI・API・Core・保存処理を揃えて導入する。不足する接続をダミーデータや操作不能なボタンで完成扱いしない。 |

### 8.2 運用上の確認と案内

- 共有時に、共有対象、公開範囲、限定受信者、独立コピーであること、停止しても取得済みコピーを回収できないことを説明する。
- 問い合わせ時には共有ID、取り込み操作ID、通知IDから対象処理と結果を追跡できるようにする。秘密情報の提出を求めない。
- 権限失効、リンク停止、通信失敗、Backend接続不足は、それぞれの状態と復旧の入口を示す。
- 後続の設計・実装で、変更する現行設計書と公開APIの説明を本書の要件に合わせる。本書作成時点では現行設計書を実装済みの説明へ書き換えない。

### 8.3 スプリントの受入確認

| ID | 確認する一連の操作 | 合格条件 |
| --- | --- | --- |
| A-01 | Workspace切り替え、Room階層の開閉、Room／DM選択 | 現在地と階層を把握でき、権限外情報と旧Workspaceの応答が混ざらない。 |
| A-02 | 複数Roomの会話・知識検索、権限取消後の再検索 | 閲覧可能な対象だけが結果・抜粋・件数へ反映され、対象を開ける。 |
| A-03 | 5種類の通知発生、対象への移動、既読、再接続 | 対象者が結果・対応待ち・招待を確認でき、重複と無断の承認が起きない。 |
| A-04 | 参加者・既定Agent表示、メニュー、ナビ・成果物パネル開閉 | 実データを表示し、既定Agentは1体のまま、元の会話と成果物操作を継続できる。 |
| A-05 | 本人設定、3テーマ、Room設定・知識、Agent詳細・知識 | 対象と管理範囲が明確で、権限に従って操作でき、未保存入力が失われない。 |
| A-06 | Room知識の選択・編集・限定共有・公開共有・既存Roomへの取り込み | 確認した知識だけを受け渡し、会話・Skill・設定・元Room権限を渡さない。管理者以外の発行・取り込みは拒否する。 |
| A-07 | Agent共有・別Workspaceへの取り込み・受け手側接続設定 | 選択した構成だけを独立Agentとして作成し、元Roomの情報・認証・権限を継承しない。 |
| A-08 | 限定リンクの第三者利用、公開リンクの未ログイン閲覧、共有停止 | 限定共有は拒否、公開共有は選択内容だけ閲覧可能。停止後の新規利用は拒否し、取り込み済みコピーは残る。 |
| A-09 | 発行・取り込みの失敗、再送、権限変更、競合 | 二重作成、部分的な成功、無認可操作、未確認の上書きが起きない。 |
| A-10 | Workspace専用メモリー廃止と旧経路からの入力 | 通常画面、API、検索、実行、復元から廃止対象を利用・再生成できない。対象外データが保持される。 |
| A-11 | 通常依頼、返信、Room自動学習、DM分離、成果物保存、export / restore | 既存の作業・権限・所有境界を維持する。学習したRoomの知識が別RoomやAgentへ自動流出しない。 |

認可・保存・取り込みの確認は実Serverと実PostgreSQL、利用者の操作は実Clientで行い、許可された操作と拒否される操作の両方を記録する。共有の検証には発行者、正規受信者、対象外利用者を用いる。検証用データの削除確認は専用の検証データで実施する。

スプリント完了は、上記の受入条件、対応する機能・非機能要件、影響する既存機能の検証に合格し、必須の未確認事項が解消した時点とする。本書の作成完了は、実装や受入確認の完了を意味しない。
