# Designs

- 責務：機能領域ごとの現行設計を、一つのテーマにつき一つの文書で管理する。
- 参照：`PRODUCT.md`と`ARCHITECTURE.md`を基準に、関係する実装とテストを確認する。
- 検証：責務・データ・接続・失敗・検証方法が一致することを確認し、過去版はGit履歴で扱う。
- 命名：`<domain>-<topic>.md`を基本とし、現在の仕組みを表す安定した名前にする。日付、`latest`、`final`は名前に入れない。
- 作成・更新：利用者が明示した場合だけ行い、作成・変更時は`README.md`の一覧も更新する。
- 本文は現在の設計だけを扱い、実装計画は`plans/`、検証結果は`reports/`へ置く。
