# React Appを完成させ、成果物を扱えるようにするプラン

- 状態: 2026-09-08更新。合意した置換方針と旧Vueの機能評価を反映した実装前プラン
- 対象: Phase 5の残作業＋Phase 7
- 技術版: [詳細プラン](native-artifact-surface-plan-phase5-7.md)
- 設計: [Native App](../docs/designs/native-app.md)、[Artifact・Surface](../docs/designs/artifact-surface.md)

## 何を実現するか

**Phase 5では、今のSamuraiに必要な操作がReact Appだけで完結するようにする。** 旧Vueの画面構成や全機能の再現は行わない。使える処理は活用し、必要な操作を今のRoom中心の設計へ組み直して、旧Vueを整理する。

**Phase 7では、仕事の成果物を開き、修正・保存できるようにする。** RoomでAgentに仕事を頼み、作った文書や表、画像、PDF、HTMLを確認する。文章や表の値はその場で直せて、Agentへ「この部分を直して」と頼むこともできる。

必要なときには、グラフやフォーム等の画面が開く。そこで入力して保存した内容は、画面を閉じても残り、次の仕事で使える。

## Phase 5で整えること

| 対象 | すること |
| --- | --- |
| 基本の仕事 | 今あるReactのWorkspace・Room・Agent・接続・依頼・添付・返信・コメント・委譲・停止を活用し、迷わず使える導線と復旧方法を揃える |
| Knowledge・Skill | 内容・保存先・根拠・変更履歴を確認し、許可された編集・保管・復元・AI更新の固定・有効状態変更を行う |
| Room管理 | 子Roomの作成、移動、人間メンバーの参加・解除・権限変更と、その影響確認を加える |
| 検索・設定 | Room内の仕事・成果物・知識を探して開く。言語、接続・Agent、学習の基本状態を必要な場所から設定する |
| 実行内容の確認 | 仕事の根拠や確認待ちを開き、必要な承認・拒否等を行う。受付と実行結果を区別する |
| 自動化 | 既存の自動実行の予定・履歴を確認して停止・再開する。新しい自動化の仕組みは作らない |
| 旧Vueの整理 | 必要な処理を移した後、旧画面・専用処理・不要な依存とテストを整理する |

これらは旧機能を評価して選んだ計画上の採用範囲。細かな配置は、Chatから必要なときに開いて戻れる形で設計する。知識画面を整理しても、保存済みのMemory・Wiki・Knowledgeを勝手に一つのデータへ変換しない。

## Phase 7で整えること

| 対象 | できるようにすること |
| --- | --- |
| 文書 | 読む、文章を直接編集する、保存する、Agentに修正を頼む |
| 表 | 見る、セルの値を直す、保存する、Agentに修正を頼む |
| 画像・PDF | 見る、ファイルを保存する、Agentに修正を頼む |
| HTML・操作画面 | 表示する、絞り込む、フォームへ入力する、データを保存する |
| 全体 | 元の仕事やRoomから開き直す、変更履歴と出所を確認する |

画像・PDFの修正は、接続したAgentが実際に対応できる範囲で行う。対応できない場合や失敗した場合は、その状態を表示する。

## なぜ今やるか

現在の通常起動は既にReactだが、知識の管理やRoomの移動などの操作が不足している。成果物だけを追加してもApp全体の置換完了にはならないため、Phase 5と7をそれぞれの完成基準で進める。

今あるAppと保存機能を活用する。旧画面に残っている表示部品を参考にしながら、現在のAppと実Agentの処理につなぐ。

旧Vueには、画面があっても保存や承認の処理が現在のAPIにつながっていない部分があった。グラフもタイトルと参照情報の表示に留まる。見た目の部品があることを完成扱いせず、実際の処理まで仕上げる。

## 画面での流れ

1. WorkspaceとRoomを選び、必要ならAgentやメンバーを設定する。
2. 知識・手順を確認して依頼し、仕事の結果や必要な確認待ちを見る。
3. 成果物カードを開き、Chatの横で内容を確認する。
4. 文章・表を自分で直すか、対象を選んでAgentへ修正を頼む。
5. 保存すると新しい版が残り、以前の内容も確認・復元できる。
6. 表やフォーム等の操作画面では、入力した内容を保存できる。
7. 検索やRoomの一覧から開き直し、Appを再起動しても同じ仕事を続けられる。

人が編集中に、新しい結果で画面や入力内容を勝手に置き換えない。保存前に閉じる場合は、保存するか破棄するか選べるようにする。

## どの順番で進めるか

| 工程 | すること | その段階の完成基準 |
| --- | --- | --- |
| A | 今回の採用・廃止一覧を現行コードと照合する | 必要な入口・保存処理・削除条件が揃う |
| B | 管理・検索・承認・成果物の保存とAgentの処理をつなぐ | 必要な操作が実際のデータと権限へ通る |
| C | Reactの基本操作・補助画面を仕上げ、成果物を開けるようにする | Phase 5の採用機能と、全対象形式の表示に到達できる |
| D | 人の編集とAgentへの修正依頼をつなぐ | 保存と履歴、変更の衝突を扱える |
| E | 操作画面から入力・保存できるようにする | 保存したデータが再表示後も残る |
| F | Vueの整理を完了し、削除後のApp・Agent・保存先で確認する | 必要な機能がReactだけで成立し、利用者確認へ進める |

Phase 5と7の番号、既存の工程A–Fは維持する。技術版には旧機能15項目の処置と、追加したPhase 5の要件・確認方法を対応付けた。

## Vueを削除する進め方

- 採用する機能は、必要な処理を移してReactで確認してから旧コードを削除する。
- 不要な機能は、参照・依存を確認して移植せず削除する。
- 学習の高度化やSkill改善はPhase 8へ残すが、旧Vue画面を保険として残さない。
- データ保存や権限の共有処理は用途を確認して活用する。旧画面の削除に合わせて利用者のデータを消さない。
- 最後に、Vueがなくても導入・起動・ビルド・必要な検証が成立することを確認する。

## 今回増やさないもの

- Word・Excelの互換編集機能。
- 画像の切り抜き・描画、PDFへの注釈やページ編集。
- 自由に画面のレイアウトを組み立てる設計ツール。
- 学習の高度化、外部アプリ製品化、専用PC・VM、配布・課金の仕組み。
- 旧Session一覧、専用カレンダー・カンバン等の全画面再現、知識の保存形式の一括変更。

Workspaceがデータを所有し、Roomごとに閲覧・編集範囲を守ること、Agentを交換できることは維持する。

## どんな問題を防ぐか

- 他のRoomや非公開の会話の成果物が見えてしまうこと。
- 人とAgentの変更がぶつかり、片方の内容が消えること。
- 保存ボタンの二度押しや通信切断で、同じ処理が重複すること。
- 生成したHTML画面が、Appの権限を使って自由にデータを読むこと。
- 保存に失敗したのに、成功したように表示すること。

変更履歴、権限確認、再送時の同一処理の判定、隔離した画面表示を組み合わせて防ぐ。

## 何をもって完成とするか

**Phase 5:** 採用した基本操作、知識・手順の管理、Room管理、検索・設定、確認待ち、自動化管理がReactだけで使える。旧Vueを整理した後も、既存データを開き、再起動・再接続後に仕事を続けられる。技術確認とドパガキくんの操作確認を分けて完了を記録する。

**Phase 7:** 実際のAppで、作成→確認→人の編集→Agentへの修正依頼→入力保存→再表示まで通す。グラフは実データを表示し、入力保存・承認は本当に保存先へ通す。Appや保存先を再起動しても内容が残り、別の保存先へ移した後も成果物・履歴・入力したデータが一致することを確認する。

実装担当がNative+Geminiで技術確認を行い、ドパガキくんが普段使うCodex/Claude Codeの公式認証での動作と、操作の分かりやすさを確認する。本番データを使わず、専用の検証環境を用意する。

Self-hostとHosted、各Agent、各OSは結果を分ける。使える環境がないものは未検証のまま報告し、全て成功したとは言わない。Windows/Linuxの実画面や配布物の最終確認はPhase 10で扱う。
