## 完了判定ルール

- `implemented`: schema / runtime or store / API or adapter / test / doctor 等の検出手段まで揃っている。
- `partial`: contract や一部の縦通しはあるが、`ARCHITECTURE.md` の責務をまだ満たし切っていない。
- `missing`: 実装として確認できる入口、保存、実行、検証がない。
- `not_backend`: 今回の backend 目標からは外すが、frontend 接続上の注意として残す。

- core backend の `partial` または `missing` が残っている限り、goal complete にしない。
- 実daemon / 実外部CLI が必要な長時間E2Eは、実装gapではなく運用検証として別枠に分ける。

## 実装後レビュー

- ARCHITECTURE適合:
  - Gateway 外部境界で扱うべき `sandbox / allowed tools / MCP config / SecretRef / path normalization / timeout / concurrency lock` の contract は前進した。
  - approved Gateway inbound では boundary policy が保存され、Host / BackendRun / BackendRunInput まで引き継がれるようになった。
  - `allowed_tools` は runtime の tool call 実行前に確認され、許可外 tool は Workspace 更新前に `ignored` になる。
  - Gateway concurrency lock は SQLite に保存され、Host 実行前の acquire、処理後の release、BackendRun cancel時の release まで入った。
  - Gateway repair は dry-run/apply の形で期限切れ pairing と期限切れ concurrency lock を同じ contract で扱えるようになり、Frontend が個別tableを推測して修復しない形に寄った。
  - Gateway boundary / lock は API と doctor からも確認できるようになった。
  - Gateway pairing / inbound / concurrency lock は `/api/health` と doctor で状態別に見えるようになり、外部入口の詰まりをログ推測だけに頼らず確認できる。
  - Gateway boundary の SecretRef / MCP config は backend/provider へ sanitized snapshot として渡るようになり、raw secret key は渡らない。
  - MCP tool は adapter contract まで進み、SecretRef resolver と secret redaction は実行経路に接続された。
  - MCP tool は stdio JSON-RPC の server process を起動して `initialize` / `tools/call` を実行できるところまで進んだ。
  - MCP tool は HTTP JSON-RPC endpoint に対しても `tools/call` を送れるようになり、SecretRef header binding と output redaction を同じ `executeMcpToolInvocation()` contract に載せた。
  - MCP config は SQLite に保存でき、API では sanitized summary として `secret_ref_ids` のみを返すようになった。
  - Runtime tool event の `mcp.call` は Gateway boundary と保存済み MCP config を照合し、許可された stdio MCP server だけを実行して Operation / ToolRun / BackendEvent に監査可能な結果を残せる。
  - Runtime `mcp.call` の stdio server は process pool で再利用でき、API server shutdown 時に pool を閉じる lifecycle contract を持った。
  - MCP process pool は `/api/health.gateway.mcp_process_pool` と doctor から process_count / max / server last_used を確認できるようになり、OpenClaw health 参照の「推測せず診断する」方向に近づいた。
  - Runtime tool event の `sandbox.exec` は Gateway boundary の sandbox policy と SecretRef resolver を通り、host / Docker / SSH / remote の executor contract で command 実行を扱えるようになった。
  - Sandbox lifecycle は `gateway_sandbox_instances` と API/health/doctor に現れ、scope=session/shared/agent と backend=docker/ssh/remote の状態を Run History から追えるようになった。
  - SecretRef material は `0600` の一時fileとして materialize し、MCP adapter 実行後に削除できるところまで進んだ。
  - ただし、これはまだHTTP transport、長寿命process管理、Docker/SSH/remote sandbox executor までは含まない。
  - Automation は retry / lock / failure state が SQLite に残るようになり、単なる「起動した記録」から durable queue に近づいた。
  - Artifact は主要kindの contract、structured metadata、image/PDF binary 実体保存、raw content API まで持てるようになった。
  - BackendEventBridge は runtime 内 helper として独立し、start/resume で同じ正規化ルールを使うようになった。
  - Resource translation は source resource に紐づく派生レコードとして保存でき、原文を上書きしない locale lifecycle の土台になった。
  - SurfaceOperation は、message / collection / structured artifact 系へ Host 内で分岐するようになり、非message操作を単なる chat prompt として扱う薄さは減った。
  - Session transcript は backend run だけでなく operation / policy / audit / artifact / tool run まで含むようになり、再開・検索・履歴の材料が増えた。
  - Session transcript / resume-state は server API から直接読めるようになり、Run History frontend が session export と resumable run を自己推測せず取得できるようになった。
  - AgentBackendRegistry は external CLI command の設定有無だけでなく、実際に PATH / 絶対path で解決できるかを Host/API/doctor へ返せるようになった。
  - AgentBackend interface の `streamEvents` seam は External CLI backend で動く形になり、BackendEventBridge / Runtime が将来 backend stream を購読するための cassette 側 contract が増えた。
  - External CLI / Codex / ClaudeCode 系 adapter は native session id を event payload から拾って BackendRun metadata に戻せるようになり、次回runで `SAMURAI_BACKEND_SESSION_ID` として渡せる session mapping が前進した。
  - BackendEventBridge は persisted event と UI projection を分け、Runtime の `backend.event.created` は要約・redaction 済みの `uiRecord` を流し、履歴APIは full persisted event を返す contract になった。
  - SamuraiNativeBackend は context assembly、provider prompt/run event construction、provider output -> backend event loop、tool call request event の責務を明示コンポーネントに分けた。
  - Gateway boundary の tool 判定は allowed/denied の snapshot として BackendEvent / ToolRun / WorkspaceChange に残るようになり、外部入力が「なぜ実行/拒否されたか」を Run History から追えるようになった。
  - ContextPreview は Memory/Wiki/Skill だけでなく session summary を持ち、backend が状態把握のために transcript 全体を再走査しなくてもよくなった。
  - External Assist は Active Memory とは別枠になり、provider出力を正本Memoryとして扱わない境界が backend prompt 上にも現れる。
- 責務分離:
  - ActionCatalog には risk / approval / policy を戻していない。
  - Secret の値は schema に入れず、参照だけを保持する方針にした。
  - SecretRef の raw value は実行直前の `materials` に閉じ、frontend/API/provider prompt へ渡るのは `secret_resolution` summary と SecretRef ID だけにした。
  - MCP stdio adapter は Gateway package 内の実行境界に閉じ、frontend や Provider prompt に process config / secret env / secret file path を渡さない。
  - MCP config record は backend store に保存し、frontend/API の通常GETは sanitized summary へ落とすことで、実行に必要な SecretRef key と表示用情報を分けた。
  - Runtime `mcp.call` は Store の config を使うが、実行条件は Gateway boundary の `allowed_tools` と `mcp_config_refs` に残す。保存済み config が存在するだけで外部入力へ自動開放しない。
  - BackendRun cancel に伴う Gateway concurrency lock release は Runtime が行い、frontend は cancel API と health/read model の再取得だけを使う。lockをUIから直接操作させない。
  - Gateway repair action は Runtime が候補を作り、Store の既存 expire 処理を通して適用する。frontend は `POST /api/gateway/repair` の dry-run/apply 結果を表示するだけに留める。
  - Gateway pairing policy は Runtime の inbound edge で評価し、frontend は `GET/POST /api/gateway/pairing-policies` と health summary を読むだけにする。ActionCatalog や UI に source trust 判定を逃がさない。
  - Gateway routing policy は Runtime の inbound edge で session key を決める。frontend は session key を自作せず、pairing/inbound/read API の `session_key` と metadata を読むだけにする。
  - Stdio MCP process pool は raw secret value を外部APIへ出さず、process key には secret value の hash のみを使う。Secret file material は process close 時に cleanup する。
  - MCP process pool health は server名と最終利用時刻だけを返し、command / env binding / secret file path / secret value は返さない。
  - Runtime `sandbox.exec` は Store の正本を書き換える機能ではなく、Gateway boundary 上の tool execution として Operation / ToolRun / BackendEvent に閉じる。Docker/SSH/remote の実行詳細は frontend や provider prompt に露出しない。
  - Sandbox lifecycle API は instance record の recreate/delete 要求だけを受け、Docker container id / SSH key path / remote daemon detail / secret file path を frontend へ返さない。
  - Skill usage は Host が選択した事実だけを保存し、Skill本文の正本は filesystem のまま維持した。
  - Skill progressive disclosure は backend context contract と provider prompt の両方に入り、frontend が後で接続しても「どの深さまで読まれたか」を判別できる。
  - Curator は直接削除・移動を行わず、ReflectionSuggestion として人間に見える候補を作るため、Workspace正本を勝手に破壊しない。
  - Evaluation も直接 patch を適用せず、execution trace review の結果を ReflectionSuggestion として残す。
  - SurfaceRenderSpec は UI実装を増やさず、backend-to-frontend contract だけを強化した。
  - SurfaceRenderSpec negotiation は frontend に判断を押し付けず、backend が requested renderer / fallback / unsupported reason を明示する contract として追加した。
  - structured SurfaceOperation は UIを実装せず、backend contract / workspace artifact / audit trail として閉じている。
  - resume-state は transcript から作る read API に留め、Session transcript の正本を増やしていない。
  - backend command probe は ExternalCliBackend 内に閉じ、Host 側へ backend 固有の PATH 解決ロジックを漏らしていない。
  - stream buffer / replay は ExternalCliBackend 内に閉じ、frontend や Host に CLI固有のstream購読実装を漏らしていない。
  - backend-native session id の抽出は ExternalCliBackend の event正規化と Runtime の run metadata更新に閉じ、Workspace正本や frontend state へ直接書かない。
  - UI projection は BackendEventBridge 内で作り、frontend や Store に tool output の間引き・redaction 判断を押し付けない。
  - ProviderAdapter は引き続き AgentBackendRegistry の差し替え口ではなく SamuraiNativeBackend 内部へ閉じた。
  - Gateway boundary の許可判定は Runtime の backend edge で行い、ActionCatalog に risk/approval/policy を戻していない。
