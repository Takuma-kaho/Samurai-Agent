# Native UI改善・利用者向けプラン

作成日: 2026-09-19

状態: 2026-09-19の実装依頼に基づき実装・検証中。

実装者向け: [詳細計画](native-ui-menu-refinement-plan.md)

## 何を整えるか

左ナビとチャットという大枠はそのままに、設定・メニュー・参加者・入力欄を、情報量が少なく統一感のある見た目へ整える。

| 場所 | 合意した変更 |
| --- | --- |
| Workspace選択 | 名前を中心に表示。固定入口・接続説明・未読の重複表示・装飾枠を除く |
| 左ナビ | 検索欄を1つ置き、その下に通知、Agentを縦に並べる |
| ロゴ | 左ナビのSamuraiアイコンと文字を削除し、Workspace名を先頭へ |
| 全体の密度 | Codex・Buzzの参考画像とCodex skillを使い、文字・アイコン・余白を小ぶりに統一。途中と完成後のスクリーンショットを目視評価 |
| Room行 | 右クリックで小さな操作メニュー。今回はUIのみ、作成・移動・名前変更などの接続は後続 |
| 参加者 | 人とAgentのアイコンを少し重ね、3〜4個程度表示。残りは人数から一覧へ。追加・権限変更も一覧から行う |
| ヘッダー | 3点ボタンはRoomメニュー、別のSVGボタンは成果物の開閉 |
| Roomメニュー | 右パネルに1画面でまとめる。タブなし。共有はボタン。成果物と同時に出さない |
| 担当Agent | チャット入力ボックスの下に置く。将来のモデル・推論レベルを右側へ追加できる構成 |
| 入力欄 | 添付・送信を整え、ショートカットの常時案内を除く |
| 設定 | 「本人設定」から「設定」へ変更。緑がかった背景や大きな装飾見出しをやめ、各テーマに揃える |
| Knowledge | 将来は全画面。概要情報と新しい画面の中身は今回作らない |

## 進める順番

1. 現在使えるRoom操作と、追加実装が必要な操作を分ける。
2. 配色・文字・アイコン・余白を共通化する。
3. 左ナビと右クリックメニューを整える。
4. Roomメニュー、参加者一覧、成果物の開閉を整理する。
5. 入力欄の下へ担当Agentを移し、「設定」の見た目を揃える。
6. 3テーマで実画面と操作を確認し、見つかった問題をまとめて直す。

## 機能を守るための条件

作業中の入力、添付、返信先、成果物の編集は、画面を開閉しても消さない。参加者の権限、共有範囲、既定Agentの変更が適用される範囲も維持する。説明を減らしても、保存失敗や操作できない理由は隠さない。

枠線を減らす際も、キーボードで選んでいる場所は分かるようにする。モデルや推論レベルの選択は将来の機能なので、今回動かないボタンを置かない。

## 今回と後続の分け方（実装中の回答を反映）

- 右クリックの作成・子Room作成・移動・名前変更はUIまで。未接続項目は無効表示とし、保存への接続は後続へ回す。ピン留め・アーカイブも後続。
- 同名Workspaceも同じ名前のまま表示し、接続先名は追加しない。
- Knowledge・学習はRoomメニューのボタンから既存画面を中央に開く。今回は新しい内容を作らない。

Knowledgeの概要や新しい画面の中身は、今回これ以上決めない。参考画像にある退出・削除・IDコピーなどを、そのまま新機能として追加しない。

## 何をもって完成とするか

合意した配置で実際に操作でき、3テーマ・通常幅・狭い幅でも崩れず、既存の仕事と保存内容を守れていること。プログラムの検査、実際の画面操作、利用者による見た目の確認は分けて記録する。

実施した検証と未確認事項は[検証記録](../reports/native-ui-menu-refinement/report.md)へ記録する。
